# Phase 6 model evaluation

> Historical research report. The current application does not include AI inference infrastructure.

## Scope and evidence standard

This is a source-level evaluation of official repositories, project documentation, model cards, and linked papers checked on 2026-11-12. No model was installed, its weights downloaded, or inference run in this environment. Reported paper/project results below are attributed to their authors, not presented as measurements by this application. Memory, latency, and cross-model target-catalog accuracy are unknown unless specifically stated.

Code being open source does not establish that pretrained weights or training data may be used commercially. Resolve the exact checkpoint terms before downloading or deploying it.

## Recommendations

1. **Primary chord candidate for a gated proof of concept:** Music X Lab's large-vocabulary ISMIR 2019 model, only after the actual checkpoint license is established and a supported runtime is reproduced. Its structured `.lab` output is more directly aligned with chord events than MOSS-Music's generated text.
2. **Secondary chord candidate:** none is ready for production selection. BTC is a research reference without verified pretrained weights. MOSS-Music may be tested as an independent comparison, but its chord accuracy is not established by the reviewed benchmark evidence.
3. **Independent chord verification:** compare predictions against legally usable, manually checked annotations using the same recording set, label vocabulary, and event/timing protocol. Do not use note transcription or source separation as a substitute for chord truth.
4. **Note transcription candidate:** Basic Pitch for isolated instrument stems/recordings, conditional on resolving Python ≥3.12 and NumPy compatibility and running actual inference. MT3 is a heavier, distinct alternative for multi-instrument evaluation.
5. **Source separation candidate:** Demucs four-stem HTDemucs, conditional on checkpoint terms and an isolated compatible PyTorch/torchaudio environment. Test with/without separation before making it mandatory in chord analysis.
6. **Not integrated:** no model in this report has passed the required supported-runtime installation, weight verification, initialization, real-audio inference, and reproducible benchmark gates. Selecting a model now would overstate what is verified.

## Compatibility, licensing, and deployment gates

- The project dependency set currently has no PyTorch, TensorFlow, ONNX Runtime, Basic Pitch, Demucs, or model weights installed. The available local interpreter is Python 3.11, whereas this application declares Python ≥3.12. Thus no selected model can truthfully be reported as tested on the supported application runtime.
- MOSS-Music's `trust_remote_code=True` example needs a security review and pinned/reviewed code before use. Do not load remote code or untrusted pickle checkpoints in the API process.
- Use a separate model environment/container when incompatible model runtimes require different PyTorch/torchaudio versions. Keep inference workers isolated from API workers.
- Before commercial release, separately review the checkpoint, training data, dataset, and source-separation model terms, as well as attribution obligations. This report is engineering research, not legal advice.
- Required acceptance evidence before enabling a model: verified immutable weight source and checksum, compatible pinned environment, actual CPU/GPU inference with measured memory and real-time factor, cancellation/OOM behavior, and benchmark results on a licensed representative set.
