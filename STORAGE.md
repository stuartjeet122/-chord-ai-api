# Asset Storage

## Providers

Application file operations use `StorageService` and the `StorageProvider` protocol in `src/music_api/storage/`.

- **Local** stores objects below a private root, validates relative paths and symlinks, streams reads, and writes by same-directory temporary file, fsync, and atomic replacement.
- **S3-compatible** uses boto3 managed transfers outside the asyncio event loop, including multipart uploads. Endpoint, bucket, region, credentials, TLS, and presigned URL lifetime are configuration values.

The configured provider is created and closed as part of FastAPI lifespan. Internal storage keys are never serialized in API responses.

## Keys and relationships

Keys are generated by the service, never accepted from clients:

```text
assets/{owner_uuid}/{asset_uuid}/{asset_type}.{detected_extension}
```

The sanitized original filename is display metadata only. Derived assets record a parent asset ID. Parent deletion is rejected while any non-deleted child exists.

`AudioAsset` records provider/key, MIME and detected extension, measured byte count, SHA-256, owner, asset type, lifecycle status, parent, timestamps, and optional future FFprobe fields. User and song foreign keys are intentionally absent in this phase because user and song tables do not exist. Owner IDs are UUIDs; production API requests fail closed until real authentication is integrated.

## Upload and integrity

1. FastAPI parses multipart content into `UploadFile`'s spooled temporary file.
2. The service streams bounded chunks to a separate private staging directory. It enforces `MAX_UPLOAD_SIZE_BYTES`, computes SHA-256 and size, sanitizes the display filename, and checks signatures against the requested asset type.
3. A quota row is locked and an upload reservation is inserted transactionally.
4. The provider writes to an opaque UUID key (atomic local promotion or completed S3 managed upload).
5. The service checks stored size and streams the object back to verify SHA-256 before committing the `AudioAsset` record and releasing the reservation.
6. On failure it releases the reservation and attempts to remove the uncommitted object. Staging files are cleaned in all outcomes.

Read-after-write checksum verification avoids loading a file into memory but doubles storage read traffic and adds latency. For the initial 100 MiB cap, this favors integrity over throughput. Revisit only with provider-native full-object SHA-256 verification that has been tested against each supported provider. Multipart parsing occurs before route-level chunk limits apply, so production ingress must also configure a request-body cap to protect parser spool space.

Signature recognition is not full media validation. Audio stream metadata/duration and decoder safety are deferred to the FFprobe ingestion phase. The API does not trust submitted `Content-Type` or filename suffix to determine the stored type.

## Lifecycle and cleanup

Lifecycle transitions are explicit:

```text
UPLOADING -> AVAILABLE | FAILED | DELETING
AVAILABLE -> PROCESSING | DELETING
PROCESSING -> AVAILABLE | FAILED | DELETING
FAILED -> PROCESSING | DELETING
DELETING -> DELETED | AVAILABLE
DELETED -> (terminal)
```

Uploads use staging outside the permanent object namespace; an asset row is created only after the object is stored and verified. Delete transitions through `DELETING`; on storage deletion failure, state returns to `AVAILABLE` so a retry can be attempted. Deletion is idempotent for a missing object. `DELETED` rows remain as metadata/audit records and do not count against quota.

`StorageService.reconcile()` reports non-deleted DB assets with missing objects, stored asset keys with no live DB row, stale staging files removed, and expired reservations removed. It does **not** delete orphan permanent objects, DB records, exports, or originals. An operator must decide retention/purge actions. Invoke reconciliation from a future scheduled maintenance worker; no scheduler is run by API workers.

## Quotas

`USER_STORAGE_QUOTA_BYTES` sets the default per-owner durable object quota. PostgreSQL quota row locking plus `upload_reservations` accounts for concurrent uploads. Used bytes exclude `DELETED` assets; reservations count against available capacity. Categories are `original_audio`, `processed_audio`, `exports`, and `analysis_artifacts`. Pre-reservation staging disk usage is temporary service overhead and is not included in the per-owner durable quota.

## Configuration

See [.env.example](./.env.example) for non-secret settings. For local storage:

```dotenv
STORAGE_PROVIDER=local
STORAGE_DIR=./storage
TEMP_DIR=./tmp
MAX_UPLOAD_SIZE_BYTES=104857600
USER_STORAGE_QUOTA_BYTES=5368709120
STORAGE_DEV_AUTH_ENABLED=true
```

For S3/MinIO:

```dotenv
STORAGE_PROVIDER=s3
STORAGE_S3_ENDPOINT_URL=https://s3.example.internal
STORAGE_S3_REGION=us-east-1
STORAGE_S3_BUCKET=music-api
STORAGE_S3_ACCESS_KEY_ID=
STORAGE_S3_SECRET_ACCESS_KEY=
STORAGE_S3_USE_TLS=true
STORAGE_S3_PRESIGNED_URL_TTL_SECONDS=300
```

Use the deployment secret manager or workload identity for credentials. S3 production configuration validates explicit credentials, and every production environment must disable the development identity header.

## API

All routes are under `/api/v1`:

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/assets` | Multipart asset upload; supports `Idempotency-Key`. |
| `GET` | `/assets?limit&offset&asset_type` | List assets owned by the caller. |
| `GET` | `/assets/{asset_id}` | Read asset metadata. |
| `GET` | `/assets/{asset_id}/download?signed=false` | Stream an asset; S3 may return a short-lived redirect for `signed=true`. |
| `GET` | `/assets/{asset_id}/children` | List derived children. |
| `DELETE` | `/assets/{asset_id}` | Delete an asset unless it has live children. |
| `GET` | `/storage/usage` | Quota and category usage. |

During development/testing only, requests use `X-Dev-User-ID: <UUID>`. This header is explicitly rejected in production; integrate the eventual JWT principal through the owner dependency before production use.

## Tests

```powershell
python -m pytest tests/test_storage_provider.py tests/test_storage_api.py -q
python -m pytest
```

Local-provider tests cover read/write/copy/list/delete, traversal and symlink rejection, and interrupted writes. API tests cover type/size enforcement, metadata privacy, owner isolation, downloads, quotas/idempotency, and production auth fail-closed behavior. S3 requires an explicitly configured isolated S3-compatible test service; none is available in this environment.
